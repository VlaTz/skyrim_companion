## Цель проекта

**Гослинг** — ИИ-компаньон в Skyrim SE. Не просто бегает за игроком и отвечает на вопросы, а:
- мыслит и имеет личность (весёлый бывший картограф, промпт — `characters/gosling/prompt.md`);
- видит мир: где мы, что вокруг, что происходит;
- действует в игре: следует, сражается, а если его отпустить — сам исследует мир;
- помнит, где мы были и куда идём (места, события, договорённости, цели);
- сам комментирует происходящее, без вопроса игрока.

Общение голосом: игрок говорит в микрофон (push-to-talk F8), Гослинг отвечает голосом Эрика
Грозного Убийцы с эмоцией по ситуации.

## Что готово

### Голосовой сервис (`companion/`, Python, FastAPI) — работает
```
микрофон (F8) → Whisper → текст → LLM → {"emotion","text"} → XTTS-v2 → динамики
```
- **STT:** faster-whisper `large-v3-turbo` на GPU (~0,25 с).
- **LLM:** любой OpenAI-совместимый сервер; сейчас OpenRouter, `anthropic/claude-haiku-5.5`
  (дёшево ~$0,0002 за реплику, ответ за 1,6–2,4 с, держит роль и JSON). Отвечает JSON-ом
  `{"emotion", "text"}`, помнит последние 10 обменов. Проверка: `python sandbox.py`.
- **TTS:** XTTS-v2 без дообучения, голос и эмоция — по референсам из игры
  (`characters/gosling/voice/<эмоция>/*.wav`, 8 эмоций Скайрима). Потоковая озвучка —
  первый звук через ~0,36 с. ~2 ГБ VRAM.
- **Запуск:** `start.bat` (= `python -m companion`). HTTP API: `/health`, `/stt`, `/tts` (с эмоцией),
  `/chat`, `/events` (WebSocket).
- **Тесты:** `tools/mic_test.py` — переозвучка своей речи **без LLM** с ручным выбором эмоции
  (так и должно остаться — это тест голоса); `tools/selftest.py` — TTS → STT по кругу.

### Данные из игры (`tools/`)
- `extract_voices.py` — реплики типа голоса из `Skyrim - Voices_ru0.bsa` → wav.
- `extract_dialogue.py` — тексты (из `*_russian.ilstrings`) и метки эмоций (TRDT из `Skyrim.esm` и DLC).
- `make_voice_refs.py` — референсы на каждую эмоцию для персонажа.
- `datasets/` и `recordings/` для работы не нужны (восстанавливаются скриптами), в git не идут.

## Принятые решения и почему

| Решение | Почему |
|---|---|
| XTTS-v2 вместо Piper + RVC | Одна модель даёт и голос, и эмоции; Piper+RVC — две модели и ровная интонация. Piper/RVC полностью удалены |
| Без дообучения XTTS | Сходство на слух достаточное; дообучать, только если появятся претензии |
| Эмоции = метки диалогов Скайрима | Референсы размечаются автоматически из `Skyrim.esm` |
| OpenAI-совместимый клиент LLM | Не привязываемся к провайдеру; сейчас OpenRouter |
| Ключ LLM в `config.local.yaml` (`llm.api_key`) | `config.yaml` в git с удалённым репозиторием на GitHub; `config.local.yaml` в `.gitignore` и подмешивается поверх |
| Не форкать NetTyan, взять идеи | NetTyan — ИИ-стример под Minecraft (мост через Java-мод), без памяти мест/целей, исследовательский код. Полезны паттерны мозга (см. ниже) |
| Mantella — не основа | Она про разговоры с NPC, без автономии и целей. Полезна как пример игровой части (голос из уст NPC, липсинк, контекст) |

## Технические заметки (грабли)
- `coqui-tts` 0.27 не работает с `transformers` 5.x → закреплено `transformers<5`.
- Coqui читает wav через `torchcodec`, которому нужен системный FFmpeg → чтение подменено на
  `soundfile` в `companion/voice/xtts.py`.
- Windows: PowerShell 5.1 пишет UTF-8 с BOM — для JSON/YAML писать файлы через Python.
- Git Bash: кириллица в аргументах curl уходит не в UTF-8 — тело запроса передавать из файла.
- Applio (обучали RVC) лежит вне проекта: `D:\Study_projects\applio` (~5–6 ГБ), больше не нужен —
  можно удалить.

## Известные проблемы
- **Качество ответов LLM** (тест `sandbox.py`): выдумывает лор (Ту'ум назвал городом), называет игрока
  «Довакин» при первой встрече вопреки промпту, иногда отвечает длиннее 1–3 предложений.
  Варианты: справка по лору в промпте/RAG, уточнение промпта, `max_tokens`, модель посильнее.
- Ответ LLM не потоковый — озвучка стартует после полного ответа.
- `{memory}` и `{game_context}` в промпте — заглушки.
- Не замерены VRAM и задержка **с запущенной игрой** (оценка: игра ~4 ГБ + XTTS ~2 + Whisper ~1 на 8 ГБ;
  если не влезет — Whisper на CPU).
- `models.yaml`: `large-v3-turbo` стоит `enabled: false`, хотя используется в `config.yaml`.

## План

### Шаг 1. Проектирование (документ в `production_logs`)
- **Протокол игра ↔ сервис:** транспорт (HTTP/WebSocket от SKSE-плагина к FastAPI), формат событий
  (локация/ячейка, позиция, бой, здоровье, время, NPC и предметы рядом, квесты, реплики) и команд.
- **Устройство мозга:** события + периодический тик; на тике Гослинг решает — молчать, прокомментировать
  или действовать; приоритеты (бой важнее болтовни); частота комментариев.
- **Память:** эпизоды (что случилось где), места (посещённые локации и впечатления), цели
  («идём в Маркарт»), договорённости; сводки, чтобы не раздувать промпт; хранилище (SQLite/Postgres).
- **Набор действий** и обратная связь о результате (в NetTyan её не было — учесть).

### Шаг 2. Минимальный мост с игрой
- Плагин `.esp` (Creation Kit): NPC Гослинг, тип голоса `MaleYoungEager`, компаньон
  (фракции фолловера), «пустая» реплика диалога для озвучки.
- SKSE-плагин (C++, CommonLibSSE-NG, Address Library): отправка контекста в сервис.
- Озвучка из уст NPC: сервис подменяет звук реплики (`.wav` + `.lip`), NPC её произносит —
  объёмный звук, липсинк и субтитры делает игра (так делает Mantella).
- Результат: Гослинг говорит в игре и знает, где вы.

### Шаг 3. Мозг
- Цикл агента с тиком, комментарии от себя (паттерны из NetTyan), память мест и целей,
  заполнение `{memory}` и `{game_context}`.

### Шаг 4. Действия
- Следовать / ждать / идти к цели / осмотреться (sandbox) / атаковать / подобрать — через пакеты ИИ NPC.
- «Отпустить исследовать»: пакет путешествия к выбранной локации + комментарии по дороге + рассказ при возвращении.

### Шаг 5. Липсинк и полировка
- Генерация `.lip` для каждого ответа, потоковый ответ LLM, замер ресурсов с игрой.

Опционально перед шагом 2: поставить Mantella на час — посмотреть, как готовый ИИ-NPC ощущается в игре.
